Practical Hands-on Assessment: Full-Stack Trip Management System
🎯 Overview
Welcome! This assessment is designed to give you a real-world preview of the tech stack and architectural patterns we use every day.

You will build a miniature, end-to-end Trip Management System. The system consists of:

A Java backend using gRPC (with REST Transcoding enabled) connected to a local Google Cloud Spanner database.
A customer-facing React frontend with dynamic timezone conversion and filtering.
An internal operations dashboard built in Retool using the REST endpoints generated by your gRPC transcoding layer.


🛠️ Detailed Requirements
1. Database & Persistence Layer (Google Cloud Spanner)
Use the Cloud Spanner Emulator (runs locally via Docker or local binaries for free).
Design and apply a database schema for Trips.
Requirements:
Store all dates/timestamps strictly in UTC.
Trip attributes must include:
TripId (String / UUID)
Name (String)
Stage (3 stages: Not Started, In Transit, Completed)
IsActive (Boolean flag)
StartTime (Timestamp in UTC)
EndTime (Timestamp in UTC)
CreatedAt (Timestamp)
Include appropriate database indices to support efficient searching by name and active status.


2. Backend Service (Java + gRPC + Transcoding)
Implement a Java service using standard gRPC.
Proto Design: You are responsible for designing the .proto service contract definitions.
gRPC Transcoding (Mandatory): Configure your gRPC service with HTTP annotations (google.api.http) so that gRPC calls are automatically exposed as REST endpoints (e.g., using grpc-gateway or gRPC-JSON transcoding).
Required Endpoints/RPCs:
ListTrips (GET /v1/trips)
Supports server-side pagination (token-based or offset-based).
Filter by search_title (partial match / substring search on Trip name).
Filter by active_at_time (ISO-8601 UTC timestamp string). A trip is considered active at a given time if StartTime <= active_at_time AND EndTime >= active_at_time.
UpdateTripStage (PATCH /v1/trips/{trip_id}/stage)
Updates the stage of a specific trip.


3. Customer Frontend (React Application)
Build a React frontend allowing users to inspect and filter trips.

Global Timezone Selector:
A top-level component or dropdown allowing the user to select their timezone (e.g., UTC, America/New_York, Asia/Kolkata, Europe/London).
Changing this selector updates how date-time fields across the app are interpreted and displayed.
Trip List Component:
Title Search: A text input with a debounced filter for searching trips by name.
Active At Time Filter:
A date-time picker where the user enters a date and time.
Timezone Logic: The local date-time entered by the user must be evaluated in the context of the selected Global Timezone, converted to a UTC ISO-8601 string, and passed to the backend API as active_at_time.
Trip Cards / Rows:
Display trip name, current stage badge (Not Started, In Transit, Completed), active state, and start/end times rendered in the user's selected global timezone.
Stage Updater: Allow changing a trip's stage via a dropdown input on each trip row/card, updating backend state.
Pagination Controls: Buttons to trigger server-side pagination calls.


4. Internal Dashboard (Retool)
Set up a simple Retool application using a free trial/developer account.

REST API Resource: Configure Retool to consume your backend's transcoded REST endpoints (/v1/trips, /v1/trips/{trip_id}/stage).
Dashboard Logic:
Include a dropdown component allowing operational users to filter trips by stage or status.
Implement Conditional Rendering: Show specific sub-panels or detail components depending on the selected trip status (e.g., show operational controls for In Transit trips, and archival summaries for Completed trips).
Provide action buttons to execute stage overrides using the REST endpoints.


📝 Deliverables & Submission Checklist
Please submit a Git repository containing:

proto/ directory: Your .proto files containing service definitions and gRPC transcoding annotations.
backend/ directory: Java backend project with Dockerfile or setup script for running with the Cloud Spanner Emulator.
frontend/ directory: React application source code.
retool/ directory: Exported JSON configuration of your Retool app or screenshots/loom video showcasing the Retool setup and conditional logic.
